# Intake, commands, and handoffs

## Source readiness

Accept assigned Scripture, an approved study handoff, a source-controlled sermon-to-devotional brief, pastoral notes, completed devotional copy, or an active Project reading plan. Do not treat a sermon application or user inference as direct Scripture. Verify a material contested claim through the appropriate Skill; ask for upstream study when the claim needs research.

For a named schedule, resolve series/year/version, requested week/day, readings, locked titles, Main Goal, Core Teaching, day roles, word limits, and interpretive cautions. Use existing context rather than asking the user to repeat it. If the schedule is missing, request the requested entries or offer a clearly separate passage-based draft; do not pretend the default plugin contains the plan. Never confuse a 2026 schedule with a 2027 schedule.

## Command compatibility

| Request | Action |
|---|---|
| Plan, weekly plan, arc, overview | Outline title/goal/teaching, readings or proposed assignments, five daily aims, cautions, and application trajectory; no full devotional prose. |
| `/week [passage or topic]` | Build a full five-day devotional week from sufficient supplied material. With only a topic and no adequate passage/source, resolve the source first. |
| `/devotional week [n]` or `/devotional build week [n]` | Read that week's active plan entries and build the full week. |
| `/devotional week [n] day [n]` or `/devotional build week [n] day [n]` | Build only the requested day from its assigned reading. |
| Tighten/revise | Make only the requested revision, preserving faithful source content and user constraints. |
| Audit/check | Diagnose first; do not rewrite unless requested. Select the relevant supporting Skill. |
| `/social` | From approved content: week gives Post 1, Post 2, Quote, Caption; day gives Post, Quote, Caption. No new teaching, hype, hashtags, or emojis unless requested. Clearly distinguish authored pull-quotes from Scripture and attributed quotes. |
| `/podcast` | Give a bounded media handoff: source title, Big Idea, two talking points, one reflection focus, prayer direction, and preserved cautions. Full episode scripting/audio belongs downstream. |
| `/imageprompt` | Give a Hub-ready text brief identifying source, intended devotional burden, possible visual concept, constraints, and cautions. No final branded image prompt or image generation. |
| `/workbook` | Route completed content to a packet/workbook workflow; a new workbook is not print polish. Preserve text and response questions in a concise handoff. |
| `/export markdown` or `/export docx` | Export supplied/finalized content in the requested format with available file tools, preserving wording. Never claim a downloadable file exists unless created. |
| `/export subsplash` | Route the exact reading-plan data and dates to platform packaging. Do not invent platform markup or mix devotional text into the schedule. |

If the user has established a plan-then-approval workflow, honor it. A reply such as "approved" continues the pending agreed step; it does not authorize unrelated asset production.

## Minimal handoff

Include only what the next owner needs: destination and requested output, source title/version and passage, approved goal/core teaching, relevant finished text or precise references to accessible source, audience/format/length, theological cautions, and unresolved source decisions. Do not perform the next owner's full work inside the handoff. If the destination lacks access to the source, include the necessary text instead of an inaccessible pointer.
